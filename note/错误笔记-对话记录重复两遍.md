# 错误笔记：对话记录/终端内容出现两遍（重复保存）

> 记录时间：2026-08-19
> 触发场景：问完问题后 AI 回复在终端显示两遍，`save` 保存的 conversation JSON 里每条消息也存了两遍

---

## 一、现象

终端：

```
AI助手: 正在思考...🤖 QwenClient: 我是通义千问……
AI助手: 我是通义千问……
```

保存的 `conversation_*.json` 里，同一轮对话的消息出现两次（一条带 `timestamp`，一条不带）：

```json
{ "role": "user",      "content": "你是谁", "timestamp": "..." },
{ "role": "user",      "content": "你是谁" },
{ "role": "assistant", "content": "我是通义千问……" },
{ "role": "assistant", "content": "我是通义千问……", "timestamp": "..." }
```

## 二、根本原因

**同一条消息被写进 `conversation_history` 两次**，来自两个不同的写入点：

1. [ai_chat_with_api.py](file:///f:/work-space/AI_GROUP/python-ai-chat/src/ai-api/ai_chat_with_api.py) 的 `chat()` 循环里调用了 `self.add_message("user", ...)` 和 `self.add_message("assistant", ...)`（带 timestamp）。
2. 而 `get_ai_response()` 调用的 `_get_streaming_response()` / `_get_traditional_response()` 内部**又各自 `conversation_history.append(...)` 了一次**（不带 timestamp）。

于是每轮对话 = 循环加一遍 + 内部再加一遍 = 两遍。

### 连带产生另外两个小问题

- **提示词里用户消息也发了两遍**：`chat()` 里先 `add_message("user", ...)` 把本轮用户消息写进历史，随后 `get_ai_response()` 内部 `get_conversation_messages()` 又会读到它、再手动 `messages.append(user_message)`，导致发给 AI 的 prompt 里用户消息重复一次。
- **终端重复显示**：流式模式下 `_get_streaming_response()` 已经逐字打印了内容，循环里又 `print(f"\r{self.ai_name}: {ai_response}")` 完整打印一遍，所以终端也出现两遍。

## 三、修复

原则：**只保留 chat() 循环这一处负责写入历史**，`get_ai_response*` 系列只负责拿回响应、不再越权改历史。

1. `_get_traditional_response()`：删除内部两行 `conversation_history.append(...)`，只返回 `response`。
2. `_get_streaming_response()`：删除内部两行 `conversation_history.append(...)`，只返回 `full_response`。
3. `chat()` 循环：把 `add_message("user", ...)` 挪到 `get_ai_response()` 之后，与 `add_message("assistant", ...)` 一起统一写入；并用 `if not self.streaming` 保护终端完整打印（流式模式已实时打印，不再二次输出）。

修复后数据流：
- prompt = [system, 历史(前几轮), 本轮用户(增强)]，用户消息只发一次；
- 历史每轮只有 1 user + 1 assistant，且都带 timestamp；
- 流式终端只显示一遍回复。

## 四、验证

写最小脚本模拟一轮对话（用假客户端、不联网）：

```
历史条数: 2
  user      | 你是谁     | 带时间戳: True
  assistant | 我是测试回复 | 带时间戳: True
OK: 无重复，修复有效
```

`python -m py_compile ai_chat_with_api.py` 通过；全文件 `conversation_history.append` 仅剩 `add_message()` 里的一处。

## 五、经验总结 / 避坑要点

1. **历史写入要有唯一责任方**：不要既在 A 处 `add_message`，又在 B 处直接 `append` 历史。要么让 `get_ai_response` 专职「取响应并写历史」，要么让 `chat()` 循环专职写历史；二选一，别两个都做。
2. **带 timestamp 与不带 timestamp 混存**是重复写入的典型痕迹：看到 JSON 里同类消息一条有 `timestamp` 一条没有，基本就是两个写入点。
3. **流式模式别二次打印**：流式函数内部已经实时打印内容，外层若再 `print(完整回复)` 就会显示两遍。可用 `if not streaming` 区分。
4. **改历史逻辑要回归一轮完整流程**：不是只看函数本身，而是从「用户输入 → 取响应 → 写历史」走一遍，确认每条消息只进一次。
